# Frontend Pass A V1 Review Packet

## Review decision requested

Review the implemented representative journey and recommend whether this branch
is ready to merge after CI and the Vercel preview are green. This packet does
not request editorial approval, publication activation, production data writes,
manual deployment, or a full-record methodology decision.

## Implemented surface

- Finder-only initial route with explicit ZIP/name search and no default sample.
- Compact selected representative header and truthful Congress scope.
- Responsive, neutral issue overview cards with deterministic discovery modes.
- Conditional reviewed-analysis section governed by the public review-state
  adapter.
- Conditional future policy-episode presentation boundary.
- Newest-first exact action ledger with filters, progressive disclosure,
  receipt sources, canonical highlighting, and one expanded row at a time.
- URL state for representative, issue, and scope with refresh and browser
  history restoration.

The visual and component rationale is recorded in
`docs/design/frontend_pass_a_v1.md`.

## Trust-boundary review

The generated public catalog is built only after merged full-record validation
and contains a closed public field set. It cannot activate analytical copy:
the public selector first requires a separately eligible publication row and
then requires exact catalog identity, scope, semantic tier, and teaser
agreement. Missing or mismatched state returns receipts-only.

F000477 Justice remains a seven-action, five-episode benchmark sample. The UI
uses `Reviewed benchmark sample`, never `Full review complete` or `Full issue
interpretation available`. No full issue synthesis is exposed. `scope=118`
cannot borrow the 119th-Congress finding.

React receives repeated-pattern/trajectory semantic roles and direction from
compiled backend meaning. It does not classify prose, infer direction from
Yea/Nay, or change ordering by party.

## Episode gap inventory

The live API intentionally returns `policy_episodes: []`. The component and
browser fixture cover title, question, member record, outcome, policy change,
affected entities, current status, both argument summaries, one-sided-source
limitation, caveats, official sources, and oldest-first exact actions. A later
milestone must define the reviewed backend episode payload and its approval and
publication gates before live episode prose appears.

and across-Congress analytical tools remain outside the primary route. No
